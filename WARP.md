# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Repository purpose & constraints

- This is a **personal DTU study repo** for notes, derivations, helper scripts, and small simulations (see `README.md`).
- Content is primarily for **personal / educational use**; it is **not** a public solution bank.
- The license (`License.md`) is **"all rights reserved"** with a personal/educational-use carve-out. Do not introduce changes that assume this is open-source or that relax the academic-integrity constraints.
- When writing or editing material that looks like an assignment or exam solution, keep it example-style and aligned with the academic integrity rules in `README.md` and `CONTRIBUTING.md` (no full ready-to-submit solutions for active coursework).

## High-level layout

Top level (simplified):

- `1. Semester/` — Intro programming & basic circuits; mostly standalone C exercises and hand-in material.
- `2. Semester/` — Higher-level math/modeling material (mainly notes and course artifacts).
- `3. semester/` — DSP, Electromagnetics, Integrated Analog Electronics; includes MATLAB helpers under `DSP/Helpers` and `Electromagnetics/Helpers`.
- `Obsidian/` — The **canonical knowledge base** (Obsidian vault): Markdown notes, formulas, course maps (MOCs), and images.
- `Obsidian/Courses/<Course>/` — Per-course sub-vaults (e.g. `DSP`, `Electromagnetics`, `Integrated Analog Electronics`) with a consistent structure:
  - `Lecture Notes/`
  - `Exercises/` (with `work/` and sometimes `LAB/` and `work/Solutions/`)
  - `Formulas/`
  - `Images/`
  - `MOC – *.md` hub files (maps of content, often auto-generated by scripts)
- `Obsidian/scripts/` — Python utilities that keep the vault consistent (wikilink checks, structure wiring, MOC generation, etc.). These are the main "code" units that automate this repo.
- `scripts/` — Currently documentation-heavy (e.g. EM method guides) rather than executable code.

The **Obsidian vault plus its scripts** is the real architectural core; semester folders mostly hold static coursework artifacts.

## Git & branching model

- `main` — Stable branch. Content here should be coherent and safe to rely on.
- `haul` — For large reorganizations/renames (to avoid breaking everything on `main`).
- Feature branches — Short-lived branches named `feat/...`, `fix/...`, `docs/...`.

When making large structural changes (moving many notes, renaming course folders, etc.), prefer working off `haul` or following the workflow described in `README.md` and `CONTRIBUTING.md`.

## Python environment & common commands

The primary automation is via the Python scripts in `Obsidian/scripts`. They assume the **current working directory is the Obsidian vault root** (`Obsidian/`).

### Environment setup (from repo root)

- Create and activate a virtual environment (PowerShell on Windows):
  - `python -m venv .venv`
  - `.\.venv\Scripts\Activate`
- Optionally install dependencies if a `requirements.txt` is later added:
  - `pip install -r requirements.txt`

> Note: At the time of writing there is no `requirements.txt`; the scripts are pure-stdlib Python.

### Running vault maintenance scripts ("tests")

From the **repo root**:

- Change into the Obsidian vault:
  - `cd Obsidian`

Then run the scripts (all are meant to be invoked from within `Obsidian/`):

- Check wikilinks for the Electromagnetics course only (fast sanity check):
  - `python scripts/check_wikilinks.py`
- Check wikilinks and cross-course links across the main courses (acts like a broader test suite):
  - `python scripts/check_wikilinks_courses.py`
- Normalize and wire course notes (DSP + Integrated Analog Electronics): frontmatter, navigation blocks, quick refs, Q↔A solution links, Dataview hubs, and image hygiene:
  - `python scripts/wire_courses.py`
- Electromagnetics-only wiring pass (same idea as `wire_courses.py` but with EM-specific quick refs and MOCs):
  - `python scripts/wire_em_vault.py`

These commands effectively serve as the **lint/test loop** for the vault:

- A **minimal check** before committing: run at least `python scripts/check_wikilinks_courses.py` from `Obsidian/`.
- A **full normalization pass**: run `wire_courses.py` and/or `wire_em_vault.py` when you have edited many notes or restructured course folders.

There is no central unit-test framework (e.g. `pytest`) configured in this repo; the Python scripts above are the main automated checks.

## Obsidian automation architecture

All four Python utilities under `Obsidian/scripts` are tightly coupled to the vault folder layout and markdown conventions.

### Common assumptions

- Current working directory is `Obsidian/` when the scripts run.
- Course roots live under `Courses/<CourseName>/`.
- Notes are Markdown files using Obsidian-style `[[wikilinks]]`.
- Many notes either already have, or will receive, YAML frontmatter: a `---` block at the top with `title`, `type`, `tags`, and `updated` fields.
- Scripts may create or update MOC files named like `MOC – <Something>.md`.
- Scripts perform in-place rewrites but often create backup copies under per-course `.backups/YYYYMMDD/` when changing files.

When editing course notes or adding new scripts, **preserve these assumptions** (e.g. keep frontmatter well-formed, do not strip `MOC – ...` files, keep `Courses/<Course>` layout consistent), or update the automation accordingly.

### `check_wikilinks.py`

- Scope: Electromagnetics course only.
- Logic:
  - Scans `Courses/Electromagnetics/**/*.md` for Obsidian-style `[[wikilinks]]`.
  - For each link, checks whether a corresponding target file exists (matching stem or `name.md`).
  - Collects any links whose targets cannot be resolved and prints a list of "Broken link in <file>: [[...]]".
  - Exits with status code `1` if any broken links are found (so it can be used as a CI-style gate).

### `check_wikilinks_courses.py`

- Scope: the main DTU courses currently modelled in the vault: `Electromagnetics`, `DSP`, `Integrated Analog Electronics`.
- Logic:
  - Defines a `COURSES` mapping from course names to their `Courses/<Course>/` roots.
  - Normalizes link text (Unicode normalization and dash harmonization) to be robust against minor naming differences.
  - For each note in each course, parses all wikilinks and attempts to resolve them **within the same course**.
  - For links that look like cross-course references (or explicit `Courses/...` paths), it distinguishes between:
    - Valid cross-course references, which are reported separately.
    - Broken links, which cause the script to exit with status code `1`.

This script is the safest **one-command health check** for the entire vault.

### `wire_courses.py`

- Scope: multi-course wiring for **DSP** and **Integrated Analog Electronics**.
- Key behavior (per course):
  - Ensures standard directories exist: `Lecture Notes/`, `Exercises/work/`, `Exercises/work/Solutions/`, `Images/`.
  - Iterates over all Markdown files (excluding `MOC – *` files) and:
    - Ensures YAML frontmatter is present, inferring `title`, `type` (lecture, formula, exercise, assignment, lab, moc), `tags`, and `updated` date.
    - Ensures a standardized **top navigation bar** at the top of each note, customized per course via `COURSE_CFG`.
    - Inserts course-specific **"quick refs"** blocks after the nav for `Formulas/` and `Exercises/work/` notes.
    - For exercise notes under `Exercises/work/`, normalizes headings like `Question 1` to `## Q1`,
      adds forward links to a corresponding `Solutions/<file> Solutions.md` file, and ensures that solutions files exist with matching back-links.
    - Appends a footer pointing back to the course's main MOC.
    - Appends **Dataview** query blocks for "recent in same folder" and "outgoing links" if not present.
    - Scrubs obvious cross-course link mistakes according to `COURSE_CFG['autofix']` (e.g. replacing EM MOCs accidentally referenced from DSP/IAE notes).
  - Ensures the main course MOC files exist (`MOC – <Course>.md`, `MOC – Lectures.md`, `MOC – Exercises.md`, etc.) and fills them with Dataview-based indexes.
  - Normalizes image embeds by moving pasted images into `Images/` and rewriting `![[...]]` references to point to the course-local `Images` folder.

This script encodes most of the **course-note conventions**. Any new automation or refactors should stay compatible with these patterns, or `wire_courses.py` should be updated in tandem.

### `wire_em_vault.py`

- Scope: **Electromagnetics** course only.
- Behavior is analogous to `wire_courses.py`, but with **EM-specific logic and content**:
  - Hard-codes `COURSE_ROOT = Courses/Electromagnetics` and ensures the same standard subdirectories exist.
  - Generates a richer set of MOCs for Electromagnetics, including topic-specific maps (`MOC – Plane Waves`, `MOC – Transmission Lines`, `MOC – EM Loss & Skin Depth`, etc.) populated via Dataview queries.
  - Builds YAML frontmatter for each note with Electromagnetics-specific tags.
  - Ensures a course-specific top navigation bar and footer referencing key EM formulas (`Formulas/Plane Waves & Power — Quick Formula Sheet`).
  - Inserts specialized quick-ref blocks for formula notes and exercises.
  - Normalizes `Question` headings and solution links for EM exercises, mirroring the Q↔A pattern in `wire_courses.py`.
  - Applies a heuristic `standardize_q9_polarization` pass to normalize certain polarization example sections into a canonical table format.
  - Appends Dataview hubs for recent notes and outgoing links.
  - Performs the same image hygiene: moves pasted images into `Courses/Electromagnetics/Images` and rewrites embeds.

For any substantial change to Electromagnetics note structure, consider whether it belongs in `wire_em_vault.py` (specialized) or `wire_courses.py` (shared), and adjust the appropriate script rather than hard-coding patterns elsewhere.

## Working with non-Python code

- `1. Semester/Basic C Programming/...` contains standalone C exercises and exam-prep files. There is no shared library or build system; compile and run these with your usual C toolchain (e.g. via a compiler task in your editor) as needed.
- `3. semester/DSP/Helpers` and `3. semester/Electromagnetics/Helpers` contain MATLAB `.m` helper functions and plotting utilities used from within MATLAB/Octave during coursework. There is no centralized MATLAB project file.

When editing these files, keep them self-contained; they are not wired into any Python or Obsidian automation.

## How future Warp agents should operate here

- Treat the Obsidian vault (`Obsidian/`) plus its Python scripts as the **source of truth** for structure and navigation.
- Before or after automated large-scale edits to notes, run the appropriate wiring scripts from within `Obsidian/` to restore consistency.
- Preserve and respect:
  - YAML frontmatter blocks
  - Top navigation lines starting with `> 🔗 [[MOC – ...]]`
  - Dataview code blocks used for indexes and hubs
  - `MOC – *.md` hub files and their roles
- When asked to generate or modify content that looks like graded coursework, stay within the academic-integrity and licensing boundaries described above.
